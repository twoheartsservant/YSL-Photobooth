YSL VALENCIA PHOTOBOOTH - LIVE PREVIEW RELAY FIX

Problem addressed:
- Main operator camera could capture photos, but the guest/secondary preview remained a blue screen.
- Previous WebRTC/BroadcastChannel signaling did not reliably deliver video frames to the guest page.

Implementation:
- Removed the WebRTC peer negotiation path from the operator and guest preview scripts.
- The operator page remains the only page that opens the physical camera.
- While the operator camera is live, operator.js draws preview frames to a canvas and posts JPEG frames to the local Flask server.
- Flask keeps only the newest frame in memory; no preview frames are saved as guest photos or written to disk.
- The guest page, the operator's embedded guest preview, and the separately launched secondary window poll the local latest-frame endpoint and display the returned image.
- Photo capture uses the received image's native dimensions (up to 1920px wide), while the small countdown/GIF prep samples remain lower resolution for speed.
- The live-frame upload and retrieval endpoints are restricted to loopback/local operator access, reject invalid JPEG data, disable caching, and expire stale frames after three seconds.
- Camera preview uses contain framing to avoid artificial zoom/cropping.

How to test:
1. Close every existing photobooth browser window.
2. Extract this ZIP into a new folder.
3. Run start.bat and use the local address opened by the launcher (127.0.0.1).
4. Connect Camera on the operator dashboard.
5. Wait for "Live camera preview connected" in the secondary preview status.
6. Check both the embedded Guest screen preview and Launch Secondary Screen window.
7. Start a session and verify the three photos still capture normally.

Validation performed in build environment:
- Python compilation passed (python -m py_compile app.py).
- JavaScript syntax checks passed (node --check for operator.js and guest.js).
- Legacy WebRTC/BroadcastChannel camera signaling references removed from the updated preview scripts.
- Flask integration tests could not be run in this environment because Flask is not installed here.
- Actual camera, secondary-monitor, and guest-screen display must be verified on the target Windows computer.

Important:
- Use the local 127.0.0.1 address launched by start.bat. The live preview relay intentionally does not expose the camera feed to remote network clients.
